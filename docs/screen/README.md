## 1. 목적

현재 대시보드의 화면 구조와 일부 컴포넌트는 이전 V1~V9, P2 보정,
산업별 가중치 방식에 맞춰져 있다. 이를 v1.5의 다음 구조에 맞게 재설계한다.

```text
12개 변수
  -> KPI 1 실질 탄소감축 성과: V1~V2
  -> KPI 2 목표 및 이행성과: W1~W2
  -> KPI 3 자본배분: C1~C4
  -> KPI 4 데이터 신뢰성: A1~A4
  -> KPI 내부 동일가중 평균 (n1=2, n2=2, n3=4, n4=4)
  -> 4개 KPI 동일가중 평균
  -> CERs Index 0~100
```

이 문서는 화면 정보구조와 사용자 흐름을 정의한다. 점수 계산 로직의 구현
명세가 아니며, 프론트엔드는 CERsIndex-batch F05가 적재한 결과만 표시한다.

### 1.1 투자자 데모 및 공개 배포 UX 검토

투자자는 첫 화면에서 제품의 차별점, 데이터 커버리지, 방법론의 방어 가능성을
빠르게 판단한다. 개인 사용자는 기업을 쉽게 찾고 점수의 의미를 오해 없이
이해해야 한다. 두 사용자의 공통 요구를 다음 우선순위로 반영한다.

1. 첫 화면에서 `공개 근거 기반 기후전환 인텔리전스`라는 제품 정의를 명확히 한다.
2. 순위보다 먼저 추적 기업 수, 점수 보유 기업 수, 최신 점수연도, 방법론 버전을
   확인할 수 있게 한다.
3. 종합점수와 4개 KPI를 항상 함께 보여 한 숫자만으로 기업을 단정하지 않게 한다.
4. 목표·넷제로 선언은 공개 사실로 표시하되 성과나 점수를 대신하는 신호처럼
   표현하지 않는다.
5. 임의 등급, `Full/Limited`, 프론트 추정 점수를 제거하고 batch 결과와
   산정 상태를 분리한다.
6. 모바일 내비게이션, 키보드 포커스, 다국어 레이아웃을 공개 서비스 수준으로
   제공한다.

Phase 1 반영 범위:

- 홈 제품 소개, 커버리지 스트립, 4 KPI 프레임, 공개 근거 신호
- 공통 헤더, 모바일 내비게이션, 푸터
- 기업 카드의 4 KPI 미니 프로필과 새 산정 상태
- 기업 상세의 4 KPI 프로필과 scoring run 메타데이터
- 섹터 카드의 중앙값, 점수 커버리지, 표본 상태
- 구 V1~V9 패널과 프론트 V3 추정 계산 제거

## 2. 고정 제약

### 2.1 반드시 유지할 홈 영역

홈 화면에서 다음 두 영역은 목적과 대표 구조를 유지한다.

1. 상단 `공개 탄소감축 대시보드` 순위 표
2. 하단 `점수 소개` 영역과 About 이동 CTA

두 영역 안의 카테고리 명칭, 상태 문구, 방법론 버전 표시는 v1.5에 맞게
교체할 수 있다. 나머지 홈 섹션은 재구성 가능하다.

### 2.2 제품 및 기술 제약

- 점수는 프론트에서 계산하거나 보간하지 않는다.
- 점수 미적재 상태는 0점과 구분해 `산정 결과 없음`으로 표시한다.
- 미공시는 batch가 변수 점수 0으로 확정했을 때만 0점으로 표시한다.
- N/A는 활동 부존재가 확인되어 batch가 비해당으로 확정한 경우만 표시한다.
- 기본 영어 경로와 `/[locale]`의
  `ko`, `en`, `zh`, `ja`, `vi`, `ru`, `id`, `th`, `bn`, `es` 구조를 유지한다.
- DB 접근은 `src/lib/server/`에서만 수행한다.
- 실제 점수와 화면 설명은 동일한 방법론 버전을 표시해야 한다.
- 섹터 비교값은 해석 정보이며 최종 점수 산식에 다시 반영하지 않는다.

## 5. 공통 화면 원칙

### 5.1 정보 우선순위

모든 점수 화면은 아래 순서를 따른다.

1. 점수 산정 여부
2. 방법론 버전과 기준연도
3. 종합점수
4. 4개 KPI 점수
5. 변수 및 근거
6. 비교와 해석

점수 숫자를 먼저 강조하되, 산정 상태와 데이터 커버리지가 숫자보다 시각적으로
묻히지 않아야 한다.

### 5.2 KPI 시각 체계

KPI 색상은 전 화면에서 고정한다.

| KPI | 의미 | 권장 색상 역할 |
|---|---|---|
| KPI 1 | 실질 탈탄소 성과 | Teal |
| KPI 2 | 감축 목표 및 이행 | Blue |
| KPI 3 | 자본배분 | Amber |
| KPI 4 | 데이터 신뢰성 | Violet |
| CERs Index | 종합점수 | Slate + Teal 강조 |

색상만으로 KPI를 구분하지 않는다. 항상 `KPI 번호 + 명칭`을 함께 표시한다.

### 5.3 상태 모델

기존 `Full/Limited/Disclosure Only`는 구 방법론의 변수 충족 구조를 전제하므로
그대로 사용하지 않는다. 화면에서는 다음 두 상태군을 분리한다.

#### 점수 상태

| 상태 | 의미 | 화면 처리 |
|---|---|---|
| `scored` | batch F05의 종합 및 KPI 결과 존재 | 점수 표시 |
| `pending` | 대상 기간이나 기업은 있으나 점수 미적재 | `산정 대기` |
| `not_scored` | 점수 산정 대상이 아니거나 run 결과 없음 | `점수 없음` |

#### 데이터 상태

| 상태 | 의미 | 화면 처리 |
|---|---|---|
| `disclosed` | 공개 근거 존재 | 값과 출처 표시 |
| `undisclosed` | 공시 가능한 정보가 없음 | batch 확정 시 0점, `미공시` 표시 |
| `not_applicable` | 물리적 활동 부존재가 확인됨 | N/A와 제외 사유 표시 |
| `unavailable` | 수집/연결 문제로 판정 불가 | 점수로 해석하지 않고 경고 |

### 5.4 공통 메타데이터

점수가 나오는 모든 화면에 아래 정보를 확인 가능하게 둔다.

- 방법론 버전
- 점수 기준연도
- scoring run 또는 업데이트 시점
- 데이터 소스 상태
- 산정 상태
- N/A 또는 미공시 항목 수

### 5.5 반응형

- 데스크톱 기준 최대 폭은 기존 `container` 규칙을 유지한다.
- 4 KPI 카드는 데스크톱 4열, 태블릿 2열, 모바일 1열이다.
- 12개 변수는 데스크톱에서 KPI별 2열 카드 또는 표, 모바일에서 아코디언이다.
- 비교표와 순위표는 모바일에서 가로 스크롤을 허용하되 첫 열을 고정한다.
- 자동 순환 UI는 `prefers-reduced-motion`을 존중하고 수동 정지 기능을 제공한다.

### 5.6 접근성

- 점수 막대는 텍스트 점수를 함께 제공한다.
- 차트에는 요약 문장 또는 표 대체 뷰를 제공한다.
- 수식은 시각 표현과 접근 가능한 텍스트 표기를 함께 제공한다.
- 탭, 아코디언, 필터, 페이지네이션은 키보드로 조작 가능해야 한다.
- 다크 모드에서도 상태색 대비 WCAG AA를 충족한다.

## 6. 화면별 기획

## H01. 홈

- Route: `/`, `/ko`, `/ja`
- 핵심 목적: 시장 전체의 점수와 데이터 상태를 빠르게 파악하고 기업/섹터 탐색으로 이동

### 유지 영역 A: 공개 탄소감축 대시보드 표

현재 `HomeScoreLeaderboard`의 위치와 순위표 역할을 유지한다.

권장 열:

```text
순위 | 기업 | KPI 1 | KPI 2 | KPI 3 | KPI 4 | CERs Index
```

요구사항:

- 최대 50개 기업, 10개 단위 순환 구조 유지 가능
- 국가 필터 유지
- 점수 없는 기업은 순위 산정에서 제외
- KPI 열은 metadata의 display order로 고정
- 표 상단에 방법론 버전과 점수 기준연도 표시
- 점수 결과가 없을 때 빈 순위표 대신 명시적인 산정 대기 안내 표시
- 자동 순환은 hover, focus, reduced motion에서 정지

### 재구성 영역

#### 1. 데이터 커버리지 스트립

순위표 바로 아래에 시장 상태를 4개 숫자로 요약한다.

```text
추적 기업 | 점수 보유 기업 | 최신 점수연도 | 방법론 버전
```

목적은 점수 평균보다 먼저 유니버스의 신뢰 범위를 설명하는 것이다.

#### 2. 4 KPI 시장 프로필

전체 점수 보유 기업의 KPI별 중앙값 또는 평균을 4개 카드로 표시한다.

- 값
- 점수 보유 기업 수
- 이전 run 대비 변화는 동일 방법론/동일 유니버스일 때만 표시
- 데이터가 없으면 카드를 숨기지 않고 `산정 결과 없음` 표시

#### 3. 전환 신호

기존 `상위 점수 기업`, `명확한 목표`, `넷제로 선언` 영역은 다음 기준으로 정리한다.

- 목표 검증: A1 SBTi 승인/커밋 상태
- 이행 진척: W2 상위 기업
- 자본배분: KPI 3 상위 기업
- 데이터 신뢰성: KPI 4 상위 기업

단순 선언보다 v1.5 변수와 직접 연결되는 신호를 우선한다.

#### 4. 섹터 탐색

- 점수 평균보다 `점수 커버리지`를 함께 표시
- 섹터 카드에 KPI 강점과 취약점 1개씩 표시
- 표본 30개 미만이면 `제한 표본` 배지 표시

### 유지 영역 B: 점수 소개

현재 홈 하단의 중앙 정렬 카드와 About CTA 목적을 유지한다.

문구는 다음 내용을 짧게 설명한다.

- 12개 변수
- 4개 KPI
- 두 단계 동일가중
- 공개 자료 기반

CTA는 `/about`으로 이동한다.

### 홈 와이어프레임

```text
[Header]

[공개 탄소감축 대시보드 표 - 유지]

[추적 기업] [점수 보유] [최신 연도] [방법론]

[KPI 1] [KPI 2] [KPI 3] [KPI 4]

[전환 신호 2열]

[섹터 카드 3열]

[점수 소개 - 유지]
```

## C02. 기업 상세

- Route: `/companies/[companyId]`
- 핵심 목적: 한 기업의 총점이 어떤 KPI와 변수에서 형성됐는지, 그 근거가 무엇인지 설명

### 1. 기업 헤더

```text
[기업명] [국가] [섹터] [산정 상태]
[CERs Index] [등급] [기준연도]
[방법론 버전] [최종 업데이트]

```

등급은 batch가 제공하고 분포 기반 경계가 확인된 경우에만 표시한다.

### 2. 4 KPI 요약

4개 KPI 카드를 동일 크기로 배치한다.

각 카드:

- KPI 점수
- 구성 변수 수
- N/A 수
- 최고/최저 변수
- 상세 변수 영역으로 이동하는 anchor

### 3. 12개 변수 상세

기존 `VariableScorePanel`의 V1~V9 목록과 `V3QualityChecklist`는 제거한다.

새 구조:

```text
KPI 1
  V1 Scope 1·2 배출성과
  V2 Scope 3 배출성과

KPI 2
  W1 감축목표 설계 수준
  W2 목표 이행 진척도

KPI 3
  C1 녹색 CAPEX 비중
  C2 저탄소 매출 비중
  C3 내부탄소가격 운영 수준
  C4 기후 거버넌스·보상 정렬

KPI 4
  A1 제3자 검증·보증
  A2 인벤토리 완전성
  A3 산정 방법론 투명성
  A4 기후 공시 체계 정합성
```

변수 행/카드의 필수 정보:

- 코드와 명칭
- 점수 또는 상태
- 산식 요약
- 입력값 요약
- 판정 근거
- source 문서 링크
- 미공시/N/A/수집불가 사유

프론트에서 입력값으로 점수를 재계산하지 않는다. 입력값은 설명용이며 점수는
batch 결과를 그대로 표시한다.

### 4. KPI별 증거 영역

#### KPI 1: 실질 탈탄소 성과

- Scope 1, Scope 2, Scope 3 시계열
- 매출 대비 집약도 추이 (V1)
- Scope 3 절대량 변화 (V2)
- like-for-like 경계 적용 여부

#### KPI 2: 목표 및 이행성과

- 유효 목표별 설계 충족 항목 (W1: 기준연도·목표연도·수준·경계·유형·중간목표·크레딧)
- 기준연도, 목표연도, 감축률
- 기대 경로 대비 현재 진척 (W2)

#### KPI 3: 자본배분

- 녹색 CAPEX / 총 CAPEX
- 저탄소 매출 / 총매출
- 내부탄소가격
- 이사회, 경영진, 보상 연계 4단계

#### KPI 4: 데이터 신뢰성

- SBTi 목표 검증 상태와 Scope별 보증 수준 (A1)
- Scope 1, Scope 2 위치기반/시장기반, Scope 3 15개 카테고리 (A2)
- 방법론 공시 4항목 (A3)
- IFRS S2/TCFD 4대 축 (A4)

### 5. 섹터 비교

- 기업 점수와 섹터 중앙값
- 기업의 섹터 내 백분위
- 4 KPI별 섹터 중앙값 비교

섹터 백분위는 보조 해석값이며 CERs Index를 변경하지 않는다.

## 7. 데이터 계약

## 7.1 현재 활용 가능한 상위 계약

현재 화면 타입에는 다음 정보가 있다.

- 기업 메타데이터
- 종합점수
- 최대 4개 category 점수
- 배출량/매출/CAPEX snapshot
- 목표 요약
- 공시/검증 요약
- 방법론 버전과 점수연도

4 KPI 요약 화면까지는 category가 v1.5 KPI로 확정된다는 전제에서 이 계약을
재사용할 수 있다.

## 7.2 추가로 필요한 변수 계약

12개 변수 상세 화면에는 batch가 소유하는 별도 결과 계약이 필요하다.

권장 읽기 모델:

```ts
type CersVariableScore = {
  code:
    | "V1" | "V2"
    | "W1" | "W2"
    | "C1" | "C2" | "C3" | "C4"
    | "A1" | "A2" | "A3" | "A4";
  kpiCode: "KPI1" | "KPI2" | "KPI3" | "KPI4";
  score: number | null;
  applicability: "applicable" | "not_applicable";
  dataStatus: "disclosed" | "undisclosed" | "unavailable";
  reasonCode: string | null;
  methodologyVersion: string;
  scoreFiscalYear: number;
  evidenceDocumentIds: string[];
};
```

실제 이름은 batch 스키마와 `docs/views.sql` 계약에 맞춘다. 위 타입은 화면에
필요한 필드의 의미를 정의한 것이며 프론트 독자 스키마로 확정하지 않는다.

## 7.3 증거 계약

변수 상세에서 다음 연결이 필요하다.

```text
company
  -> scoring run
  -> KPI score
  -> variable score
  -> input facts
  -> evidence document/page
```

페이지 번호나 source locator가 없다면 문서 단위 링크까지만 제공하고, 화면에서
근거 위치를 추정해 표시하지 않는다.

## 7.4 점수 없는 상태

F05 결과가 없는 동안:

- 홈 순위표: 산정 대기 상태
- 기업 카드: 종합점수 대신 `점수 없음`
- 기업 상세: 배출/목표/문서는 표시하되 점수 영역에 미적재 안내
- 비교: 점수 없는 기업도 선택 가능하나 비교 가능한 데이터만 표시
- 섹터: 점수 커버리지 0%와 실제 기업 수를 구분

## 8. 다국어 콘텐츠 규칙

- 화면 구조, 카드 순서, 변수 코드는 지원하는 10개 locale에서 동일하다.
- `Scope`, `SBTi`, `CAPEX`, `IFRS`, `GHG Protocol`은 공인 표기를 우선한다.
- 숫자와 날짜는 locale formatter를 사용한다.
- 긴 번역 제목이 카드 폭을 깨지 않도록 최소 높이를 고정하지 않는다.
- 방법론 문구의 변경은 한 언어만 수정하지 않고 10개 지원 locale을 함께 갱신한다.
- 변수 코드와 anchor는 locale과 무관하게 동일하다.

## 11. 화면 완료 기준

### 공통

- 10개 지원 locale에서 같은 화면 구조와 변수 순서를 제공한다.
- 방법론 버전과 점수 기준연도를 확인할 수 있다.
- 프론트에서 점수를 계산하지 않는다.

- 점수표와 차트가 키보드 및 모바일에서 사용 가능하다.

### 홈

- 상단 공개 탄소감축 대시보드 표가 유지된다.
- 표의 4개 차원이 v1.5 KPI와 일치한다.
- 하단 점수 소개 영역이 유지된다.
- 점수 미적재 상태에서 허위 순위가 표시되지 않는다.

### 기업 상세

- 종합점수와 4 KPI가 같은 scoring run을 사용한다.
- 12개 변수 코드가 중복/누락 없이 표시된다.
- 변수 점수와 evidence를 추적할 수 있다.
- 구 V1~V9 및 구 V3 체크리스트 문구가 남지 않는다.

### 비교

- 최대 3개 기업을 같은 기준연도/방법론 여부와 함께 비교한다.
- 12개 변수에서 0, N/A, 점수 없음이 구분된다.

### 섹터

- 점수 커버리지와 표본 수가 평균점수와 함께 표시된다.
- 섹터 백분위가 최종 점수와 혼동되지 않는다.

### 방법론

- 집계식과 12개 변수 설명이 v1.5 문서와 일치한다.
- `/about/logic`과 `/score-logic`이 상충하는 콘텐츠를 제공하지 않는다.

- 점수 미적재 기업의 임의 추정
